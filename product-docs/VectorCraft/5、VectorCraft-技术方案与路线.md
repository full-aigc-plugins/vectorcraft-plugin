## 1. 技术决策与替代方案

| ADR | 决策与原因 | 替代与反转条件 |
| :--- | :--- | :--- |
| ADR-001 | 独立 Skills 仓库 + 插件内不可变发布副本，保持单一知识事实源 | 拒绝兄弟目录符号链接；若宿主提供可靠依赖解析再增加适配 |
| ADR-002 | 复用官方 Rust CLI，通过受控 MCP/argv 调用 | 不重写编辑引擎；缺少必要 API 时先提交能力缺口 |
| ADR-003 | 拟用 TypeScript、Node.js 24 LTS 编排，复用现有生态经验 | 实现前固定补丁版本和依赖；不以文档证明兼容 |
| ADR-004 | SQLite 账本 + 内容寻址文件，面向本地单用户工作区 | 多机器协作出现时再评估服务状态存储 |
| ADR-005 | 公共任务与素材协议由 ArtCraft OpenSpec 持有 | 领域仓只持有映射与消费测试，不另定义公共字段 |
| ADR-006 | 技术门禁和创作审阅分离；已有授权持续有效 | 不把每次调用改为人工审批；超范围行为才需新授权 |

## 2. 独立技能供应链

`vectorcraft-skills` 已独立发布。插件通过 `skills.lock.json` 固定来源标签 `v0.1.0-dev.2`、提交和完整技能摘要；SKILL.md、引用与可移植脚本仍由技能源仓库维护。执行 `python3 scripts/vendor/skill_vendor.py check --offline` 核对内置快照。技能源发布不代表完整宿主或创作验收通过。

| 阶段 | 输入 | 失败规则 |
| :--- | :--- | :--- |
| resolve | repository + immutable tag | tag 不可解析或来源未允许则停止 |
| verify | commit + tree digests | 任一文件漂移则拒绝同步 |
| package | skills inventory | 拒绝包外链接与重复技能名 |
| audit | clean install fixture | 单独安装技能仍能解析公开依赖 |

## 3. 领域计划的编译策略

| 能力 | 行为边界 | 状态 |
| :--- | :--- | :--- |
| 路径形状与坐标 | 定义画板坐标、单位、路径控制点、闭合性与描边；不可把预览像素当成路径事实。 | 计划中 |
| 组合与布尔操作 | 记录参与对象 ID、布尔运算与结果对象身份，保留修改前检查点；操作失败不丢失原对象。 | 计划中 |
| 品牌色与文字 | 以显式 token 绑定品牌色而非全文件颜色替换；保留文本内容与字体依赖，轮廓化输出记录可编辑性损失。 | 计划中 |
| 画板与变体 | 每个画板有稳定 ID、名称、尺寸和输出映射；预览顺序与导出范围明确，避免索引基准混淆。 | 计划中 |
| 交换格式能力范围 | 原生 .vectorcraft 与 SVG、PDF、PNG 分别验证；遇到不可交换效果时报告栅格化范围并保留原工程。 | 计划中 |
| 品牌变体更新 | 根据 token 与素材依赖更新相关变体，核对无关对象属性与输出没有变化。 | 计划中 |

规划器输出声明式计划；编译器逐项检查当前运行时支持的命令、字段、单位和边界，生成类型化操作序列。所有源对象先 inspect 获取真实 ID。编译产物记录 planHash 与 capabilitySnapshotHash；未支持映射返回 unsupported_mapping。只有通过能力验证的操作才能进入提交阶段。

## 4. 安装与运行时管理

运行时管理分为 discover、verify、install、probe、activate、upgrade、rollback。用户已有兼容运行时可以复用；显式路径必须验证。下载时固定制品 URL 与摘要，拒绝目录穿越和解压符号链接逃逸，先验证再执行。版本目录不覆盖活动二进制，升级操作保留旧回执。平台未验收显示 unverified，不假定 universal ZIP 证明所有架构可用。

## 5. 提交、恢复与产物协议

任务使用持久化意图、幂等键和单写租约。对于无外部 taskId 的同步 CLI，也需记录 attemptId、进程身份、工程检查点和预期输出摘要。进程死亡后检查原生工程与输出，不能因为没有远程 taskId 就直接重跑。大文件写入与账本登记之间用 reconcile 处理窗口。原生工程与导出分别验收，依赖和字体无法打包时列出清单及可验证的获取方式。

## 6. 测试计划与验收资产

| 测试层 | 必须覆盖 | 证据 |
| :--- | :--- | :--- |
| contract | 缺字段、未知字段、幂等冲突、版本冲突 | schema + fixture results |
| adapter | 真实命令发现、模式差异、错误映射 | runtime identity + transcript |
| recovery | 提交后断线、迟到结果、取消未确认 | ledger before/after + duplicate count |
| native | 制作 Logo 与图标资产，交付 .vectorcraft、SVG 和 PNG；修改品牌色后更新所有绑定的变体，并保留无关颜色。 | project reopen + output inspection |
| host | 干净宿主安装、升级、卸载保留用户数据 | host/version/platform + logs |

## 7. 实施路线

| 阶段 | 交付 | 进入下一阶段条件 |
| :--- | :--- | :--- |
| D0 | 双语文档与 OpenSpec 基线 | 文档、链接、规范校验通过；实现任务仍未完成 |
| M1 | 独立技能与运行时适配 | 清洁环境安装、摘要检查、真实 MCP 调用 |
| M2 | 专业领域完整闭环 | 代表任务、工程重开、输出解码、局部修改 |
| M3 | ArtCraft 跨插件协作 | 版本传播、局部失效、断线恢复与幂等 |
| M4 | 宿主与发布验收 | 宿主实装与多平台证据；市场清单一致 |

采用依赖顺序，不虚构交付日期或开发工时。每项 OpenSpec 任务列出需求 ID、责任角色、产物与验证。先失败用例，再最小实现；没有实际证据不勾选。

## 8. 运行、升级与发布

插件版本、技能版本、上游 CLI 版本和协议版本独立演进。发布矩阵固定四者组合，生成各宿主清单与市场元数据，验证远端提交和锁文件一致。文档基线不发布插件安装包；首次可安装版本以 M4 门禁通过为条件。新版本出现问题时恢复之前验证的插件/技能/CLI 组合，状态迁移不兼容时从备份恢复。
